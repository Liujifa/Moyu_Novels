# 多页章节验证记录

验证日期：2026-11-17。使用真实 HTTP 响应及现有 `collect_chapter_pages` 流程抽查，不导入个人书库，不保留小说正文到仓库。

## 原因

- mopbook 的第一页地址形如 `5N3FC-1.html`，后半页为 `5N3FC-1-2.html`。旧版仅处理下划线与查询参数，未识别连字符页码。
- 16zw 的后半页为 `79746279_1.html`，按钮却写作“下一章”。旧版先过滤按钮文字，导致有效分页链接被跳过。
- 16zw 的段落位于 `document.writeln(qsbs.bb('Base64 字面量'))` 中，旧版正文解析会删除 script，因而找不到正文。

各样本均访问了当前章的后半页，并在真正的下一章之前停止。字符数反映当时经清洗提取的文本长度，站点更新后可能变化。本记录不代表已验证整本书全部章节。

## 完整性保护

- 分页后的章节标题变化、正文缺失、分页循环或超过页数上限时失败，不把半章写入成功缓存。
- 明确的章节列表优先于外层混合区域，避免把最新章节及推荐书混入目录。
- 更新章节缓存版本，旧版半章缓存需重新抓取。已有 TXT 不自动改写，需要重新下载。
- 只对字面量中的已知 Base64 写入形式解码，不执行任意页面脚本。

## v1.0.2 动态目录与整本验证

mopbook 详情页默认显示前 100 章，后续目录使用脚本加载；其分页下拉框是数字参数而非可访问 URL。这是 v1.0.1 中“目录包含尚未读取的脚本分页”报错的原因，与 Cookie 是否导入成功是两个独立问题。

v1.0.2 增加 `chapterPageAjxa` 协议支持：从页面读取书籍标识及页码范围，从公开脚本读取固定参数，按原站的 AES-CBC 请求格式调用目录接口。只解析明确的字符串配置，不执行远程脚本，也不依赖域名白名单。所有请求复用下载器原有会话、Cookie、限速、重试和取消流程。

## v1.0.3 washai 目录与限流验证

对 [样本详情页](https://book.washai.net/book/1262260513468562259.html) 的检查发现：详情页只提供最新章节，完整目录的首页为 `indexList-书籍ID.html`，后续为 `indexList/书籍ID/页码.html`。优先跟随「全部目录」，按 `data-index-id` 行级标记提取正文链接，并归一化两种目录路由后，共读到 21 页、2040 个不同章节 URL，与页面声明数量一致。多卷章节会重新编号，因此末章的编号不等于总章数。

旧调度默认间隔 0.3 秒，无服务端提示时仅短暂等待 2、4、8 秒，重开下载又会恢复默认速度；实际请求触发 HTTP 429。下表记录本次保守速率验证，两轮使用不同的连续章节，没有生成冒充整本小说的部分 TXT：

| 验证方式 | 实际请求及结果 | 耗时 |
| --- | --- | --- |
| 探测：4 秒起步，遇到限流后降至约 6.4 秒 | 完成 45 章，46 次请求：45 个 200、1 个 429 | 250.2 秒 |
| 新版「慢速稳定」：单路，至少间隔 6 秒 | 完成另 45 章，45 次请求全部 200，没有 429；最小实际间隔 6.0 秒 | 264.7 秒 |

已成功章节保留在本地章节缓存，可以续传。这是连续章节抽样，不代表整本 2040 章已下载，也不保证网站日后仍使用相同额度。同一网络的其他请求也可能影响结果。

新版按主机共享冷却和调度，遇到 429 后从至少 60 秒的冷却开始，随后保持单路慢速，不再在短暂成功后加速。降速记录和剩余冷却会保存到下载目录，重启后读取；`Retry-After` 秒数和 HTTP 日期会被遵守。虚拟时钟回归测试覆盖长等待、共享 GET/POST 额度、取消、并发在途请求合并降速、重启与探测上限，共 165 项测试通过。
